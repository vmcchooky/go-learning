Biến, hằng số & zero value
var, :=, const, iota, phạm vi biến và zero value
▼
var:=constiotacơ bản
var age int       // 0
var name string  // ""
var ok bool       // false

x := 10          // chỉ dùng trong function
y, z := 1, 2

const Pi = 3.14159
const (
    Red = iota
    Green
    Blue
)
Ý chính: Biến trong Go luôn có zero value nên bạn có thể khai báo trước, gán sau. := là cách khai báo ngắn gọn nhất cho biến cục bộ.
Lỗi hay gặp: Biến cục bộ khai báo mà không dùng sẽ làm chương trình không biên dịch. Ngoài function thì không dùng được :=.
Khi nào dùng: Dùng := khi kiểu dữ liệu đã rõ từ biểu thức bên phải. Dùng var khi muốn nhấn mạnh kiểu hoặc cần zero value trước.
Điều kiện & switch
if, if với init, switch cơ bản, fallthrough vừa đủ dùng
▼
ifswitchfallthroughcơ bản
if score >= 8 {
    fmt.Println("gioi")
} else if score >= 5 {
    fmt.Println("dat")
} else {
    fmt.Println("rot")
}

if err := doSomething(); err != nil {
    return err
}

switch day {
case "Sat", "Sun":
    fmt.Println("weekend")
case "Mon":
    fmt.Println("new week")
default:
    fmt.Println("normal day")
}
Ý chính: Go không có toán tử ba ngôi nên if và switch là hai công cụ rẽ nhánh chính. switch tự dừng sau mỗi case, không cần break.
Lỗi hay gặp: Biến tạo ở phần init của if chỉ sống trong chính câu lệnh đó. fallthrough có tồn tại nhưng nên dùng rất ít.
Khi nào dùng: Dùng if cho vài điều kiện ngắn. Dùng switch khi có nhiều nhánh rõ ràng và muốn code dễ đọc hơn.
Vòng lặp for & range
for kiểu C, while-style và range qua slice, map, string
▼
forrangebreakcontinuecơ bản
// C-style
for i := 0; i < 3; i++ {
    fmt.Println(i)
}

// while-style
sum := 1
for sum < 10 {
    sum += sum
}

nums := []int{10, 20, 30}
for i, v := range nums {
    fmt.Println(i, v)
}

for _, r := range "Go" { // r là rune
    fmt.Printf("%c\n", r)
}
Ý chính: Go chỉ có một từ khóa lặp là for. range giúp duyệt dữ liệu gọn và an toàn hơn so với tự quản lý chỉ số trong nhiều trường hợp.
Lỗi hay gặp: Trong for i, v := range nums, v là bản copy của phần tử hiện tại. Muốn sửa phần tử thật thì phải ghi qua nums[i].
Đọc sau: range còn dùng được với map, channel, số nguyên, và iterator function ở các phần nâng cao hơn.
Array
Kích thước cố định và mang ngữ nghĩa value type
▼
arrayfixed-sizevalue typecơ bản
a := [3]int{1, 2, 3}
b := a       // copy toàn bộ mảng
b[0] = 99

fmt.Println(a) // [1 2 3]
fmt.Println(b) // [99 2 3]
Ý chính: Array có độ dài là một phần của kiểu dữ liệu. Gán array cho biến khác là copy dữ liệu, không phải chia sẻ bộ nhớ như slice.
Lỗi hay gặp: Người mới thường nhầm array với slice. [3]int và [4]int là hai kiểu hoàn toàn khác nhau.
Khi nào dùng: Dùng khi kích thước cố định và thật sự có ý nghĩa. Trong code Go hằng ngày, bạn sẽ gặp slice nhiều hơn.
Slice
Danh sách động, len/cap, append và backing array
▼
sliceappendlen/capcơ bản
s := []int{10, 20, 30}
s = append(s, 40)

sub := s[1:3]
sub[0] = 99

fmt.Println(s)   // [10 99 30 40]
fmt.Println(sub) // [99 30]

var nilSlice []int
emptySlice := []int{}
fmt.Println(nilSlice == nil) // true
fmt.Println(len(emptySlice)) // 0
Ý chính: Slice là “cửa sổ nhìn vào một vùng dữ liệu”. Nó có len, cap và thường là cấu trúc danh sách bạn dùng hằng ngày trong Go.
Lỗi hay gặp: Hai slice có thể chia sẻ cùng backing array, nên sửa slice con có thể làm đổi slice gốc. nil slice và empty slice đều có độ dài 0 nhưng không hoàn toàn giống nhau.
Khi nào dùng: Dùng cho tập dữ liệu có kích thước thay đổi. Đây là lựa chọn mặc định thay cho array trong phần lớn chương trình.
Map
Key-value, tra cứu nhanh, delete và comma-ok idiom
▼
mapdeletecomma-okcơ bản
scores := map[string]int{
    "Ann": 9,
    "Bob": 8,
}

scores["Cat"] = 10
delete(scores, "Bob")

score, ok := scores["Ann"]
fmt.Println(score, ok)

var m map[string]int
fmt.Println(m["missing"]) // 0
// m["x"] = 1             // panic
Ý chính: Map dùng để lưu dữ liệu theo cặp key-value và tra cứu rất nhanh. Khi đọc một key, bạn có thể nhận thêm biến ok để biết key đó có tồn tại hay không.
Lỗi hay gặp: Đọc từ nil map thì an toàn, nhưng ghi vào nil map sẽ panic. Thứ tự duyệt map không cố định.
Khi nào dùng: Dùng khi cần tra cứu theo tên, id, mã, hay bất kỳ khóa nào thay vì theo vị trí số như slice.
Pointer & address-of
Hiểu &, *, nil pointer và khi cần truyền địa chỉ
▼
*&pointercơ bản
x := 42
p := &x

fmt.Println(*p) // 42
*p = 100
fmt.Println(x)  // 100

type Node struct {
    Val  int
    Next *Node
}

n := &Node{Val: 1}
Ý chính: Pointer cho phép bạn làm việc với địa chỉ của một giá trị. Khi sửa qua pointer, giá trị gốc cũng thay đổi.
Lỗi hay gặp: Dùng nil pointer sẽ gây panic khi dereference. Go không có pointer arithmetic như C/C++.
Khi nào dùng: Dùng khi muốn hàm sửa dữ liệu gốc, khi struct lớn và không muốn copy nhiều, hoặc khi kiểu dữ liệu tự nhiên đã chứa liên kết như linked list/tree.
new() vs make()
Hai cách khởi tạo rất dễ nhầm với người mới
▼
newmakeinitcơ bản
p := new(int)           // *int, zero value = 0
nums := make([]int, 0, 8)
seen := make(map[string]bool)
jobs := make(chan int, 2)

fmt.Println(*p)    // 0
fmt.Println(nums)  // []
fmt.Println(seen)  // map[]
Ý chính: new(T) trả về *T. make(T) chỉ dùng cho slice, map, chan và trả về chính giá trị đã sẵn sàng dùng.
Lỗi hay gặp: new(map[string]int) không cho bạn một map sẵn sàng ghi dữ liệu. Muốn dùng được ngay, hãy dùng make(map[string]int).
Khi nào dùng: Hầu hết khi làm việc với slice, map, chan bạn sẽ dùng make. new ít gặp hơn trong code beginner.
Packages
Tách code theo package, export/unexport và import cơ bản
▼
packageimportexportcơ bản
package mathutil

import (
    f "fmt"
    _ "image/png" // chạy side effects, thường là init()
)

func Add(a, b int) int { return a + b } // export
func helper() {}                        // chỉ dùng trong package

func Demo() {
    f.Println(Add(1, 2))
}
Ý chính: Package là cách Go tổ chức code. Tên bắt đầu bằng chữ hoa thì có thể dùng từ package khác, chữ thường thì không.
Lỗi hay gặp: Blank import _ không phải để “bỏ qua lỗi”, mà để lấy side effects. Dot import tồn tại nhưng người mới nên tránh vì làm code khó đọc.
Khi nào dùng: Tạo package mới khi một nhóm hàm/kiểu dữ liệu đủ liên quan và bạn muốn tách chúng khỏi main.
Modules & go.mod
Đơn vị quản lý dependency của Go và cấu trúc dự án tối thiểu
▼
modulego.moddependencycơ bản
// go.mod
module github.com/user/myapp

go 1.26

require golang.org/x/sync v0.20.0

// thư mục tối thiểu
// myapp/
//   go.mod
//   main.go
//   internal/auth/
Ý chính: Module là “project unit” của Go. File go.mod ghi tên module, version Go, và các dependency chính.
Lỗi hay gặp: Người mới hay nhầm package với module. Một module có thể chứa nhiều package.
Đọc sau: Thư mục internal/ giúp giới hạn package nào được phép import code bên trong. Hữu ích khi dự án lớn hơn.
Error handling
Kiểm tra lỗi theo kiểu Go: trả về error và xử lý sớm
▼
errorif err != nil%wtrung cấp
func loadConfig() error {
    data, err := os.ReadFile("config.json")
    if err != nil {
        return fmt.Errorf("load config: %w", err)
    }
    _ = data
    return nil
}

err := loadConfig()
if err != nil {
    fmt.Println(err)
}

if errors.Is(err, os.ErrNotExist) {
    fmt.Println("file chưa tồn tại")
}
Ý chính: Trong Go, lỗi thường là một giá trị trả về chứ không phải exception. Cách viết quen thuộc là “gọi hàm, kiểm tra err, xử lý sớm rồi return”.
Lỗi hay gặp: Bỏ qua lỗi bằng _ quá sớm sẽ làm bug khó tìm. Khi thêm ngữ cảnh, dùng %w để còn kiểm tra lại bằng errors.Is.
Đọc sau: errors.As, custom error type, và errors.Join hữu ích hơn khi hệ thống bắt đầu lớn lên.
defer
Dọn tài nguyên tự động khi function kết thúc
▼
defercleanupLIFOtrung cấp
func readFile(path string) error {
    f, err := os.Open(path)
    if err != nil {
        return err
    }
    defer f.Close()

    name := "first"
    defer fmt.Println(name) // in "first"
    name = "second"

    return nil
}
Ý chính: defer rất hợp cho các việc “mở ở đâu thì đóng ở đó” như file, mutex, hay tracing. Nó làm code cleanup đáng tin cậy hơn khi có nhiều đường return.
Lỗi hay gặp: Đối số của lời gọi defer được tính ngay tại dòng đó, không phải lúc function kết thúc. Vì vậy ví dụ trên sẽ in first.
Khi nào dùng: Dùng ngay sau khi tài nguyên được mở thành công: Open, Lock, Start, hay các thao tác cần đảm bảo cleanup.
panic & recover
Dành cho lỗi không thể tiếp tục, không phải cách xử lý lỗi thông thường
▼
panicrecovererror boundarytrung cấp
func safeRun(fn func()) {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("panic:", r)
        }
    }()

    fn()
}

safeRun(func() {
    panic("boom")
})
Ý chính: panic dành cho trạng thái chương trình không còn hợp lệ hoặc lỗi không thể tiếp tục. Trong luồng business bình thường, hãy trả về error thay vì panic.
Lỗi hay gặp: recover() chỉ có tác dụng khi được gọi trực tiếp bên trong một hàm defer đang chạy trong lúc panic lan ra ngoài.
Khi nào dùng: Thường chỉ dùng ở ranh giới chương trình như worker loop, HTTP middleware, hoặc framework code để tránh một panic làm sập toàn bộ tiến trình.
