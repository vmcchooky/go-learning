1. Cú pháp lõi
Biến, hằng số & zero value
var, :=, const, iota, naming, scope, nhiều kiểu gán biến
▼
var:=constiotanamingcơ bản
// Khai báo trước, gán sau
var age int          // 0
var name string      // ""
var active bool      // false

// Khai báo và khởi tạo đồng thời
var port int = 8080
var title = "Go"

// Khai báo ngắn / suy luận kiểu
count := 10          // chỉ dùng trong function
msg, ok := "done", true

// Gán nhóm nhiều biến
left, right := 1, 2
left, right = right, left

// Bỏ qua giá trị không cần
value, exists := map[string]int{"go": 1}["go"]
_, month, day := 2026, 6, 7

// Hằng số
const Pi = 3.14159
const AppName = "myapp"

// Iota
const (
    Sunday = iota
    Monday
    Tuesday
)

// Inline statement assignment
if n := len(title); n > 0 {
    fmt.Println(n)
}
Ý chính: Biến trong Go luôn có zero value nên bạn có thể khai báo trước rồi mới gán sau. := là cách khai báo ngắn gọn nhất cho biến cục bộ khi kiểu đã rõ.
Các cách gán cần nhớ: Explicit declaration, initialization, short declaration, multiple assignment, blank identifier assignment, constant assignment, iota assignment, và inline assignment trong if/switch.
Blank identifier _: Đây không chỉ là “thùng rác” để bỏ giá trị, mà còn là cách nói với compiler rằng bạn cố ý không dùng kết quả đó. Dùng khi thật sự không cần giá trị; đừng biến _ thành cách né xử lý err.
Quy tắc đặt tên: Tên package nên ngắn, lowercase, không gạch dưới. Tên export bắt đầu bằng chữ hoa. Tên local thường dùng mixedCaps. Tránh lặp nghĩa kiểu user.UserName nếu package đã là user.
Lỗi hay gặp: Biến cục bộ khai báo mà không dùng sẽ làm chương trình không biên dịch. := phải tạo ít nhất một biến mới trong cùng scope và rất dễ gây shadowing nếu dùng trong block con.
Ép kiểu (Type Conversions)
Ép kiểu tường minh giữa số, string, []byte, []rune và các bẫy thường gặp
▼
conversionfloat64(x)[]byte[]runecơ bản
count := 10
ratio := 2.5
sum := float64(count) + ratio

fmt.Println(sum) // 12.5
fmt.Println(int(3.99)) // 3: cắt phần thập phân

word := "đây"
raw := []byte(word)
runes := []rune(word)

fmt.Println(len(raw))   // số byte UTF-8
fmt.Println(len(runes)) // số rune

text := string(raw)
fmt.Println(text) // "đây"

fmt.Println(string(65))      // "A"
fmt.Println(strconv.Itoa(65)) // "65"

n := 256
fmt.Println(int8(n)) // 0: cắt theo 8 bit thấp
Ý chính: Go không tự ép kiểu ngầm giữa các kiểu số hay giữa các kiểu gần giống nhau. Muốn đổi kiểu, bạn phải viết rõ T(v).
Quy tắc cần nhớ: Ép từ float sang int sẽ cắt phần lẻ. Ép sang kiểu nhỏ hơn như int64 -> int8 có thể làm mất dữ liệu hoặc overflow theo số bit của kiểu đích.
Lỗi hay gặp: string(65) tạo chuỗi từ mã Unicode/rune, không phải chuỗi chữ số "65". Muốn đổi số sang text, hãy dùng strconv.
Khi nào dùng: Dùng khi trộn nhiều kiểu số, làm việc với dữ liệu byte từ file/network, hoặc cần xử lý Unicode bằng []rune thay vì từng byte.
Điều kiện & switch
if, if với init, switch expression, type switch, fallthrough
▼
ifswitchtype switchfallthroughcơ bản
score := 7
if score >= 8 {
    fmt.Println("gioi")
} else if score >= 5 {
    fmt.Println("dat")
} else {
    fmt.Println("rot")
}

name := "gopher"
if n := len(name); n > 0 {
    fmt.Println("len =", n)
}

day := "Sat"
switch day {
case "Sat", "Sun":
    fmt.Println("weekend")
case "Mon":
    fmt.Println("new week")
default:
    fmt.Println("normal day")
}

// switch không có biểu thức = thay cho if-else chain
x := -3
switch {
case x < 0:
    fmt.Println("negative")
case x == 0:
    fmt.Println("zero")
default:
    fmt.Println("positive")
}

// type switch
var anyValue any = "go"
switch v := anyValue.(type) {
case int:
    fmt.Println("int:", v)
case string:
    fmt.Println("string:", v)
default:
    fmt.Printf("unknown: %T\n", v)
}
Ý chính: Go không có toán tử ba ngôi nên if và switch là hai công cụ rẽ nhánh chính. switch tự dừng sau mỗi case, không cần break.
Quy tắc: Không cần ngoặc tròn quanh điều kiện. Biến tạo ở phần init của if hoặc switch chỉ sống trong chính câu lệnh đó và các nhánh liên quan.
Lỗi hay gặp: fallthrough tồn tại nhưng nên dùng rất ít vì nó làm luồng đọc khó hơn. type switch chỉ dùng được với giá trị interface như any.
Vòng lặp for & range
C-style, while-style, infinite, range qua slice, map, string, channel, integer
▼
forrangebreakcontinuelabelcơ bản
// C-style for
for i := 0; i < 10; i++ { }

// While-style
for n < 100 { n *= 2 }

// Infinite loop
for { break }

// Range over slice
for i, v := range []int{1, 2, 3} {
    fmt.Println(i, v)
}

// Range over map
m := map[string]int{"a": 1, "b": 2}
for k, v := range m {
    fmt.Println(k, v)
}

// Range over string (rune-safe)
for i, r := range "hello" {
    fmt.Printf("%d: %c\n", i, r)
}

// Range over channel
ch := make(chan int, 2)
ch <- 10
ch <- 20
close(ch)
for v := range ch {
    fmt.Println(v)
}

// Range over integer
for i := range 5 {
    fmt.Println(i) // 0..4
}

// Loop variable scoping (Go 1.22+)
for _, v := range []int{1, 2, 3} {
    go func() { fmt.Println(v) }()
}

// Label với break
Outer:
for row := range 3 {
    for col := range 3 {
        if row == col {
            break Outer
        }
    }
}
Ý chính: Go chỉ có một từ khóa lặp là for. range giúp duyệt dữ liệu gọn và an toàn hơn so với tự quản lý chỉ số trong nhiều trường hợp.
Quy tắc quan trọng: Với string, range duyệt theo rune chứ không phải từng byte. Với channel, vòng lặp dừng khi channel bị đóng.
Lỗi hay gặp: Trong for i, v := range nums, v là bản copy của phần tử hiện tại. Muốn sửa phần tử thật thì phải ghi qua nums[i]. Thứ tự duyệt map cũng không cố định.
Đọc sau: Từ Go mới hơn, range còn hỗ trợ iterator function. Nên học sau khi đã quen các kiểu range cơ bản.
2. Cấu trúc dữ liệu
Array
Kích thước cố định và mang ngữ nghĩa value type
▼
arrayfixed-sizevalue typecơ bản
a := [3]int{1, 2, 3}
b := a              // copy toàn bộ mảng
b[0] = 99

names := [...]string{"go", "lang"} // compiler tự suy ra length

fmt.Println(a) // [1 2 3]
fmt.Println(b) // [99 2 3]

// So sánh được nếu phần tử so sánh được
fmt.Println(a == [3]int{1, 2, 3})
Ý chính: Array có độ dài là một phần của kiểu dữ liệu. Gán array cho biến khác là copy dữ liệu, không phải chia sẻ bộ nhớ như slice.
Lỗi hay gặp: Người mới thường nhầm array với slice. [3]int và [4]int là hai kiểu hoàn toàn khác nhau.
Khi nào dùng: Dùng khi kích thước cố định và thật sự có ý nghĩa. Trong code Go hằng ngày, bạn sẽ gặp slice nhiều hơn, còn array thường xuất hiện ở các trường hợp dữ liệu cố định hoặc low-level.
Slice
Danh sách động, len/cap, append, copy và backing array
▼
sliceappendlen/capcopycơ bản
s := []int{10, 20, 30}
s = append(s, 40)

buf := make([]int, 2, 5) // len=2, cap=5

sub := s[1:3]            // share backing array
sub[0] = 99

safeSub := s[1:3:3]      // chặn cap của subslice

dst := make([]int, len(s))
copy(dst, s)

fmt.Println(s)       // [10 99 30 40]
fmt.Println(sub)     // [99 30]
fmt.Println(safeSub) // [99 30]

var nilSlice []int
emptySlice := []int{}
fmt.Println(nilSlice == nil) // true
fmt.Println(len(emptySlice)) // 0
Ý chính: Slice là “cửa sổ nhìn vào một vùng dữ liệu”. Nó có len, cap và thường là cấu trúc danh sách bạn dùng hằng ngày trong Go.
Quy tắc cần nhớ: append có thể tạo backing array mới nếu vượt quá cap. Khi biết trước kích thước gần đúng, nên pre-allocate bằng make để giảm số lần cấp phát lại.
Lỗi hay gặp: Hai slice có thể chia sẻ cùng backing array, nên sửa slice con có thể làm đổi slice gốc. nil slice và empty slice đều có độ dài 0 nhưng không hoàn toàn giống nhau, nhất là khi encode JSON.
Khi nào dùng: Dùng cho tập dữ liệu có kích thước thay đổi. Đây là lựa chọn mặc định thay cho array trong phần lớn chương trình.
Map
Key-value, tra cứu nhanh, delete, clear và comma-ok idiom
▼
mapdeleteclearcomma-okcơ bản
scores := map[string]int{
    "Ann": 9,
    "Bob": 8,
}

counts := make(map[string]int)
counts["go"]++

scores["Cat"] = 10
delete(scores, "Bob")
clear(counts) // Go 1.21+

score, ok := scores["Ann"]
fmt.Println(score, ok)

var m map[string]int
fmt.Println(m["missing"]) // 0
// m["x"] = 1             // panic

for k, v := range scores {
    fmt.Println(k, v)
}
Ý chính: Map dùng để lưu dữ liệu theo cặp key-value và tra cứu rất nhanh. Khi đọc một key, bạn có thể nhận thêm biến ok để biết key đó có tồn tại hay không.
Quy tắc cần nhớ: Dùng make(map[K]V) nếu bạn muốn tạo map rỗng để ghi dữ liệu dần. delete với key không tồn tại vẫn an toàn.
Lỗi hay gặp: Đọc từ nil map thì an toàn, nhưng ghi vào nil map sẽ panic. Thứ tự duyệt map không cố định và map thường không an toàn cho concurrent read/write nếu không có đồng bộ hóa.
Khi nào dùng: Dùng khi cần tra cứu theo tên, id, mã, hay bất kỳ khóa nào thay vì theo vị trí số như slice.
Pointer & address-of
Hiểu &, *, nil pointer, pointer assignment và khi cần truyền địa chỉ
▼
*&pointernilcơ bản
x := 42
p := &x

fmt.Println(*p) // 42
*p = 100
fmt.Println(x)  // 100

// Pointer assignment = copy địa chỉ
p2 := p
*p2 = 200

var p3 *int
fmt.Println(p3 == nil) // true

type Node struct {
    Val  int
    Next *Node
}

n := &Node{Val: 1}
Ý chính: Pointer cho phép bạn làm việc với địa chỉ của một giá trị. Khi sửa qua pointer, giá trị gốc cũng thay đổi.
Quy tắc cần nhớ: &x lấy địa chỉ của x, còn *p truy cập giá trị mà p đang trỏ tới. Gán pointer cho pointer khác là copy địa chỉ, không copy dữ liệu đằng sau.
Lỗi hay gặp: Dùng nil pointer sẽ gây panic khi dereference. Go không có pointer arithmetic như C/C++.
Khi nào dùng: Dùng khi muốn hàm sửa dữ liệu gốc, khi struct lớn và không muốn copy nhiều, hoặc khi kiểu dữ liệu tự nhiên đã chứa liên kết như linked list/tree.
new() vs make()
Hai cách khởi tạo rất dễ nhầm với người mới
▼
newmakeinitcơ bản
type Node struct{ Val int }

p := new(int)            // *int, zero value = 0
node := new(Node)       // *Node

nums := make([]int, 0, 8)
seen := make(map[string]bool)
jobs := make(chan int, 2)

fmt.Println(*p)    // 0
fmt.Println(nums)  // []
fmt.Println(seen)  // map[]
Ý chính: new(T) trả về *T. make(T) chỉ dùng cho slice, map, chan và trả về chính giá trị đã sẵn sàng dùng.
Phân biệt dễ nhớ: new tạo “một giá trị zero và trả địa chỉ của nó”. make tạo “một slice/map/channel đã được runtime chuẩn bị đủ cấu trúc bên trong để dùng ngay”.
Lỗi hay gặp: new(map[string]int) không cho bạn một map sẵn sàng ghi dữ liệu. Muốn dùng được ngay, hãy dùng make(map[string]int).
Khi nào dùng: Hầu hết khi làm việc với slice, map, chan bạn sẽ dùng make. new ít gặp hơn trong code beginner.
3. Tổ chức dự án
Packages
Tách code theo package, export/unexport, import alias, blank import và init
▼
packageimportexportinitcơ bản
package mathutil

import (
    f "fmt"
    _ "image/png" // chạy side effects, thường là init()
    . "math"      // tồn tại nhưng nên hạn chế
)

func Add(a, b int) int { return a + b } // export
func helper() {}                        // chỉ dùng trong package

func Demo() {
    f.Println(Add(1, 2))
}

func init() {
    // chạy tự động trước main()
}
Ý chính: Package là cách Go tổ chức code. Tên bắt đầu bằng chữ hoa thì có thể dùng từ package khác, chữ thường thì không.
Quy tắc: Mỗi file Go thuộc đúng một package. Một thư mục thường tương ứng với một package. Package name nên ngắn, lowercase và mô tả vai trò của code bên trong.
Lỗi hay gặp: Blank import _ không phải để “bỏ qua lỗi”, mà để lấy side effects. Dot import tồn tại nhưng người mới nên tránh vì làm code khó đọc và khó trace nguồn identifier.
Khi nào dùng: Tạo package mới khi một nhóm hàm/kiểu dữ liệu đủ liên quan và bạn muốn tách chúng khỏi main hoặc dùng lại ở nơi khác.
Modules & go.mod
Đơn vị quản lý dependency của Go, go mod init và cấu trúc dự án tối thiểu
▼
modulego.moddependencycơ bản
// go.mod
module github.com/user/myapp

go 1.26

require golang.org/x/sync v0.20.0

// khởi tạo module
// go mod init github.com/user/myapp
// go mod tidy

// thư mục tối thiểu
// myapp/
//   go.mod
//   main.go
//   internal/auth/
Ý chính: Module là “project unit” của Go. File go.mod ghi tên module, version Go, và các dependency chính.
Phân biệt: Một module có thể chứa nhiều package. Package là đơn vị tổ chức code, còn module là đơn vị quản lý dependency và version.
Lỗi hay gặp: Người mới thường tạo project mà quên go mod init, hoặc nhầm import path của package với tên thư mục cục bộ.
Đọc sau: Thư mục internal/ giúp giới hạn package nào được phép import code bên trong. Hữu ích khi dự án lớn hơn.
4. Kiểm soát luồng nâng cao
Error handling
error, wrapping, errors.Is, errors.As và custom error cơ bản
▼
errorif err != nil%werrors.Istrung cấp
var ErrNotFound = errors.New("not found")

type NotFoundError struct{ Name string }
func (e *NotFoundError) Error() string {
    return fmt.Sprintf("%s not found", e.Name)
}

func loadConfig() error {
    data, err := os.ReadFile("config.json")
    if err != nil {
        return fmt.Errorf("load config: %w", err)
    }
    _ = data
    return nil
}

err := loadConfig()
if err != nil {
    fmt.Println(err)
}

if errors.Is(err, os.ErrNotExist) {
    fmt.Println("file chưa tồn tại")
}

var nfe *NotFoundError
if errors.As(err, &nfe) {
    fmt.Println(nfe.Name)
}
Ý chính: Trong Go, lỗi thường là một giá trị trả về chứ không phải exception. Cách viết quen thuộc là “gọi hàm, kiểm tra err, xử lý sớm rồi return”.
Quy tắc nên theo: Khi thêm ngữ cảnh vào lỗi, dùng fmt.Errorf(... %w ...) để sau này còn kiểm tra lại bằng errors.Is hoặc errors.As.
Lỗi hay gặp: Bỏ qua lỗi bằng _ quá sớm sẽ làm bug khó tìm. Dùng %v thay vì %w khi wrap lỗi sẽ làm mất chuỗi kiểm tra chuẩn của Go.
Đọc sau: errors.Join, sentinel errors, và phân tầng custom error sẽ hữu ích hơn khi hệ thống bắt đầu lớn lên.
defer
Dọn tài nguyên tự động khi function kết thúc, LIFO và evaluate tham số
▼
defercleanupLIFOtrung cấp
func readFile(path string) error {
    f, err := os.Open(path)
    if err != nil {
        return err
    }
    defer f.Close()

    defer fmt.Println("last")
    defer fmt.Println("first") // chạy trước vì LIFO

    name := "first"
    defer fmt.Println(name) // đối số được evaluate ngay
    name = "second"

    return nil
}

func double(n int) (result int) {
    defer func() { result *= 2 }()
    result = n
    return
}
Ý chính: defer rất hợp cho các việc “mở ở đâu thì đóng ở đó” như file, mutex, hay tracing. Nó làm code cleanup đáng tin cậy hơn khi có nhiều đường return.
Quy tắc cần nhớ: Nhiều defer chạy theo thứ tự LIFO. Tham số của lời gọi defer được evaluate ngay tại dòng đó, nhưng closure bên trong có thể đọc trạng thái mới hơn lúc function sắp kết thúc.
Lỗi hay gặp: Nhiều người tưởng defer fmt.Println(name) sẽ in giá trị cuối cùng của name, nhưng thực ra nó in giá trị tại thời điểm gặp câu lệnh defer.
Khi nào dùng: Dùng ngay sau khi tài nguyên được mở thành công: Open, Lock, Start, hay các thao tác cần đảm bảo cleanup.
panic & recover
Dành cho lỗi không thể tiếp tục, recover trực tiếp trong defer
▼
panicrecovererror boundarytrung cấp
func safeRun(fn func()) {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("panic:", r)
        }
    }()

    fn()
}

safeRun(func() {
    panic("boom")
})

func helperRecover() any { return recover() }

func wrongRecover() {
    defer func() {
        fmt.Println(helperRecover()) // nil
    }()
    panic("boom")
}
Ý chính: panic dành cho trạng thái chương trình không còn hợp lệ hoặc lỗi không thể tiếp tục. Trong luồng business bình thường, hãy trả về error thay vì panic.
Quy tắc cần nhớ: recover() chỉ có tác dụng khi được gọi trực tiếp bên trong một hàm defer đang chạy trong lúc panic lan ra ngoài.
Lỗi hay gặp: Nhiều người gọi recover() gián tiếp qua một hàm khác rồi thắc mắc vì sao nhận nil. Đó là hành vi đúng theo spec.
Khi nào dùng: Thường chỉ dùng ở ranh giới chương trình như worker loop, HTTP middleware, goroutine supervisor, hoặc framework code để tránh một panic làm sập toàn bộ tiến trình.
