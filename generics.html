Type parameters, inference & instantiation
generic functions, type inference, explicit instantiation và tư duy dùng generics đúng chỗ
▼
type paramsinferenceinstantiationtrung cấp
func Map[T, U any](items []T, fn func(T) U) []U {
    out := make([]U, len(items))
    for i, item := range items {
        out[i] = fn(item)
    }
    return out
}

labels := Map([]int{1, 2, 3}, func(n int) string {
    return fmt.Sprintf("n=%d", n)
})
fmt.Println(labels) // [n=1 n=2 n=3]

func Zero[T any]() T {
    var zero T
    return zero
}

fmt.Println(Zero[int]()) // explicit instantiation
Ý chính: Generics cho phép một hàm làm việc với nhiều kiểu dữ liệu mà vẫn giữ type safety ở compile time. Đây là cách Go tái sử dụng thuật toán mà không cần rơi về any quá sớm.
Quy tắc cần nhớ: Go thường suy luận được type arguments từ tham số đầu vào, nên nhiều lời gọi không cần viết [T] tường minh. Khi compiler không có đủ thông tin để suy luận, bạn phải explicit instantiation như Zero[int]().
Lỗi hay gặp: Nhiều người tưởng generics là “dynamic typing”, nhưng không phải. Type parameter vẫn được kiểm tra rất chặt ở compile time. Một lỗi khác là generic hóa cả những hàm vốn chỉ phục vụ một domain type cụ thể.
Khi nào dùng: Dùng khi bạn có cùng một thuật toán áp dụng tự nhiên cho nhiều type khác nhau như map, reduce, filter, min/max, container helpers.
Constraints, comparable & ~
type sets, underlying types, custom constraints và vì sao comparable rất quan trọng
▼
constraintscomparable~trung cấp
type Signed interface {
    ~int | ~int8 | ~int16 | ~int32 | ~int64
}

func Sum[T Signed](items []T) T {
    var total T
    for _, item := range items {
        total += item
    }
    return total
}

type UserID int64
fmt.Println(Sum([]UserID{10, 20, 30})) // 60

func IndexOf[T comparable](items []T, target T) int {
    for i, item := range items {
        if item == target {
            return i
        }
    }
    return -1
}
Ý chính: Constraint là “hợp đồng kiểu” cho type parameter. Chúng được mô tả bằng interface kiểu mới của generics: không phải để lưu value runtime, mà để định nghĩa tập type được phép dùng.
Quy tắc cần nhớ: comparable cần thiết khi bạn muốn dùng == hoặc !=. Dấu ~ nghĩa là chấp nhận mọi defined type có underlying type phù hợp, nên UserID vẫn thỏa ~int64.
Lỗi hay gặp: slice, map, và func không thỏa comparable. Nhiều người cũng tự viết lại constraint ordered cơ bản, trong khi với nhiều case thật tế bạn có thể dùng luôn cmp.Ordered của stdlib.
Khi nào dùng: Dùng custom constraint khi thuật toán cần toán tử, method, hoặc một nhóm type cụ thể mà any là quá rộng.
Generic types, methods & zero values
generic struct, methods trên type generic, zero value pattern và các gotcha phổ biến
▼
generic structmethodszero valuetrung cấp
type Stack[T any] struct {
    items []T
}

func (s *Stack[T]) Push(v T) {
    s.items = append(s.items, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.items) == 0 {
        var zero T
        return zero, false
    }
    n := len(s.items) - 1
    v := s.items[n]
    var zero T
    s.items[n] = zero // clear reference để GC có thể thu hồi object cũ nếu cần
    s.items = s.items[:n]
    return v, true
}

var s Stack[string] // zero value vẫn dùng được
s.Push("go")
s.Push("gen")
v, ok := s.Pop()
fmt.Println(v, ok) // gen true
Ý chính: Generic type rất hợp cho container và helper structures như stack, set, cache wrapper, option/result containers. Chúng cho phép tái sử dụng một kiểu dữ liệu cho nhiều loại phần tử khác nhau.
Quy tắc cần nhớ: Method trên generic type dùng lại type parameter từ receiver như Stack[T]. Khi cần zero value của T, idiom chuẩn là var zero T. Nếu container bỏ phần tử ra khỏi slice nhưng backing array còn sống lâu, việc clear slot cũ giúp tránh giữ reference không cần thiết. Nhiều type generic trong Go vẫn nên cố thiết kế để zero value dùng được.
Lỗi hay gặp: Generic methods với type parameter mới riêng cho method không được hỗ trợ như trong một số ngôn ngữ khác. Ngoài ra, đừng generic hóa mọi domain model như User hay Order nếu điều đó chỉ làm API khó đọc hơn.
Khi nào dùng: Dùng cho data structures và reusable building blocks, không phải để “biến mọi thứ thành framework”.
Iter package & range-over-func
iter.Seq, iter.Seq2, iter.Pull và custom iterators trong Go 1.23+ vẫn dùng tốt ở 1.26.4
▼
iter.Seqrange-over-funcPullnâng cao
import "iter"

func UpTo(n int) iter.Seq[int] {
    return func(yield func(int) bool) {
        for i := range n {
            if !yield(i) {
                return
            }
        }
    }
}

for v := range UpTo(5) {
    fmt.Println(v)
}

next, stop := iter.Pull(UpTo(3))
defer stop()
fmt.Println(next()) // 0 true

all := slices.Collect(UpTo(5))
fmt.Println(all) // [0 1 2 3 4]
Ý chính: iter và range-over-func là một hướng rất mạnh của Go hiện đại để xây iterator không cần channel. Chúng đặc biệt hợp cho traversal trong memory, library APIs, và các adapter giữa collection với pipeline xử lý.
Quy tắc cần nhớ: iter.Seq[V] là một hàm nhận yield. Iterator dừng khi hết dữ liệu hoặc khi yield trả về false. Nếu dùng iter.Pull và không đọc đến hết, bạn nên gọi stop(), thường bằng defer stop().
Lỗi hay gặp: Nhiều người nhầm iterator kiểu này với goroutine/channel iteration. Chúng không phải là concurrency primitive. Một bẫy khác là gọi slices.Collect trên một sequence vô hạn rồi tự treo chương trình.
Đọc sau: Đây là tính năng xuất hiện từ Go 1.23 và vẫn là một phần rất đáng chú ý trong Go 1.26.4. Nếu làm thư viện, bạn nên cân nhắc naming conventions của package iter như All, Values, Backward.
Generic type aliases
type alias có type parameters, specialization và phân biệt alias với defined type trong Go 1.26.4
▼
type aliasgeneric aliasidentitynâng cao
type Result[T any] struct {
    Data T
    Err  error
}

type IntResult = Result[int]

type Node[T any] struct {
    Value T
    Next  *Node[T]
}

type GenericNode[T any] = Node[T]

var r IntResult = Result[int]{Data: 42}
var n GenericNode[string] = Node[string]{Value: "hello"}
fmt.Println(r.Data, n.Value)
Ý chính: Generic type alias cho phép bạn đặt tên khác cho một generic type hoặc specialize một generic type thành dạng cụ thể hơn. Đây là công cụ tốt cho compatibility layer, migration, hoặc tạo các tên domain-friendly.
Quy tắc cần nhớ: Alias không tạo type identity mới. type IntResult = Result[int] vẫn là đúng cái type đó, chỉ có tên khác. Điều này khác với type MyResult[T any] Result[T], vốn tạo defined type mới.
Lỗi hay gặp: Nhiều người kỳ vọng alias sẽ cho method set hay identity riêng như defined type, nhưng không phải. Đây là điểm rất quan trọng khi thiết kế API hoặc refactor thư viện.
Đọc sau: Generic aliases là phần tương đối mới trong lịch sử generics của Go, và ở Go 1.26.4 bạn có thể xem chúng là tính năng ổn định để dùng thực tế.
slices, maps, cmp & idiomatic stdlib
stdlib packages sống cùng generics: sort, compare, collect, clone, equal và các pattern tiện dụng
▼
slicesmapscmptrung cấp
scores := map[string]int{
    "go":  10,
    "gen": 20,
    "map": 15,
}

keys := slices.Sorted(maps.Keys(scores))
fmt.Println(keys) // [gen go map]

clone := maps.Clone(scores)
fmt.Println(maps.Equal(scores, clone)) // true

nums := []int{3, 1, 4, 1, 5}
slices.Sort(nums)
nums = slices.Compact(nums) // phải gán lại
fmt.Println(nums)

fmt.Println(cmp.Compare(10, 20)) // -1
fmt.Println(cmp.Or("", "fallback"))
Ý chính: Một phần rất thực tế của generics trong Go là stdlib giờ có thêm nhiều helper mạnh và type-safe qua các package như slices, maps, và cmp. Đây là các API bạn sẽ dùng thường xuyên hơn nhiều so với việc tự viết generics phức tạp.
Quy tắc cần nhớ: maps.Keys trả về iterator và thứ tự không đảm bảo; nếu cần thứ tự ổn định, hãy dùng slices.Sorted. Nhiều hàm của slices như Compact, Delete, Insert trả về slice mới và bạn cần gán lại.
Lỗi hay gặp: Người mới hay quên rằng map iteration order là không xác định, rồi bất ngờ khi output đổi thứ tự. Một lỗi khác là gọi helper của slices mà quên dùng giá trị trả về.
Khi nào dùng: Trước khi tự viết generic utility mới, hãy kiểm tra xem stdlib đã có thứ bạn cần chưa. Rất nhiều bài toán thường gặp đã được giải quyết sẵn và khá “đúng Go”.
