Ý chính: Hàm trong Go khai báo bằng func, có danh sách tham số, và có thể có hoặc không có giá trị trả về. Hàm là đơn vị tổ chức logic quan trọng nhất trong ngôn ngữ.
Quy tắc cần nhớ: Go truyền tham số theo value. Tuy nhiên nếu tham số là slice, map, pointer, channel, function, hay interface thì “giá trị được copy” vẫn có thể tham chiếu tới dữ liệu bên dưới, nên nhìn từ bên ngoài bạn vẫn thấy hiệu ứng thay đổi. Tên bắt đầu bằng chữ hoa là exported, chữ thường là chỉ dùng trong package.
Lỗi hay gặp: Go không hỗ trợ function overloading, default arguments, hay named arguments. Bạn không thể khai báo hai hàm cùng tên chỉ khác kiểu tham số.
Khi nào dùng: Tách hàm khi một đoạn logic có thể đặt tên rõ ràng, tái sử dụng được, hoặc giúp flow của code dễ đọc hơn.
Multiple returns & named results
nhiều giá trị trả về, error pattern, named return và naked return
▼
multiple returnnamed returnerrorcơ bản
// Multiple return values
func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("division by zero")
    }
    return a / b, nil
}

result, err := divide(10, 2)
fmt.Println(result, err)

cache := map[string]int{"go": 100}
score, ok := cache["go"]
fmt.Println(score, ok) // 100 true

// Named return values
func minMax(nums []int) (min, max int) {
    if len(nums) == 0 {
        return // naked return tự động trả về 0, 0
    }
    min, max = nums[0], nums[0]
    for _, n := range nums[1:] {
        if n < min { min = n }
        if n > max { max = n }
    }
    return // naked return: trả về min, max
}

_, _ = divide(10, 0) // bỏ qua hoàn toàn bằng blank identifier
Ý chính: Go cho phép hàm trả về nhiều giá trị, và đây là một trong các idiom quan trọng nhất của ngôn ngữ. Pattern phổ biến nhất là (value, error).
Quy tắc cần nhớ: Named return values thực chất là các biến đã được khai báo sẵn trong scope của hàm. Chúng hữu ích khi kết hợp với defer hoặc khi tên kết quả giúp code rõ nghĩa hơn. Khi không cần một giá trị trả về, dùng _ để bỏ qua.
Lỗi hay gặp: Naked return trong hàm dài dễ làm code khó đọc vì người đọc phải nhớ biến nào đang được trả về. Với hàm ngắn thì ổn, nhưng với hàm dài thường nên return rõ ràng.
Khi nào dùng: Dùng nhiều giá trị trả về cho các trường hợp tự nhiên như value, ok, value, err, hoặc các cặp dữ liệu liên quan như min, max.
Variadic, function types & callbacks
...T, function type, functions as values, callback và higher-order functions
▼

// Variadic function
func sum(nums ...int) int {
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}

fmt.Println(sum(1, 2, 3)) // 6
nums := []int{1, 2, 3}
fmt.Println(sum(nums...)) // unpack slice

// Function type
type Predicate func(int) bool

func filter(nums []int, fn Predicate) []int {
    var result []int // idiomatic: dùng nil slice thay vì []int{}
    for _, n := range nums {
        if fn(n) {
            result = append(result, n)
        }
    }
    return result
}

isEven := func(n int) bool { return n%2 == 0 }
evens := filter([]int{1, 2, 3, 4}, isEven)
fmt.Println(evens) // [2 4]
Ý chính: Trong Go, hàm là first-class value. Bạn có thể gán hàm cho biến, truyền hàm vào hàm khác, và trả về hàm như mọi giá trị khác.
Quy tắc cần nhớ: Tham số variadic ...T phải là tham số cuối cùng. Khi đã có slice cùng kiểu, có thể “unpack” bằng cú pháp slice....
Lỗi hay gặp: Function value có thể là nil. Gọi một function value nil sẽ panic ở runtime. Ngoài ra, function values chỉ so sánh được với nil, không so sánh trực tiếp với nhau bằng ==.
Khi nào dùng: Dùng variadic cho các API như logging, formatting, collect values. Dùng higher-order function khi muốn truyền “hành vi” vào một pipeline hay helper chung.

func makeCounter() func() int {
    count := 0
    return func() int {
        count++
        return count
    }
}

c := makeCounter()
fmt.Println(c()) // 1
fmt.Println(c()) // 2

func(msg string) {
    fmt.Println("run once:", msg)
}("boot")

// Loop variable rebind mỗi iteration (Go 1.22+)
callbacks := []func(){}
for i := 0; i < 3; i++ {
    callbacks = append(callbacks, func() { fmt.Println(i) })
}
for _, cb := range callbacks {
    cb() // 0, 1, 2
}

// Một ứng dụng phổ biến: functional options
type Server struct{ port int }
type Option func(*Server)

func WithPort(p int) Option {
    return func(s *Server) { s.port = p }
}
Ý chính: Closure là hàm có thể “nhớ” và dùng các biến ở scope bên ngoài. Đây là cách rất mạnh để giữ state nhỏ gọn mà không cần tạo struct riêng cho mọi trường hợp.
Quy tắc cần nhớ: Biến bị capture không bị copy theo nghĩa “giá trị bất biến”; closure giữ tham chiếu logic tới biến trong scope của nó. Với loop variables, Go 1.22+ đã rebind mỗi iteration nên bug cũ quen thuộc đã được sửa.
Lỗi hay gặp: Closure giữ state nên nếu dùng từ nhiều goroutine cùng lúc mà không đồng bộ, bạn vẫn có thể tạo race condition.
Khi nào dùng: Dùng cho callback, factory hàm, middleware, và các pattern như functional options khi muốn cấu hình object theo cách linh hoạt.
Methods, receivers & method values
value receiver, pointer receiver, method set, method expression và method value
▼
receivermethod setmethod valuetrung cấp
type Point struct{ X, Y float64 }

// Value receiver — không thay đổi gốc
func (p Point) Distance() float64 {
    return math.Sqrt(p.X*p.X + p.Y*p.Y)
}

// Pointer receiver — có thể thay đổi gốc
func (p *Point) Scale(factor float64) {
    p.X *= factor
    p.Y *= factor
}

// Method expression: receiver là arg đầu tiên
dist := Point.Distance
fmt.Println(dist(Point{3, 4})) // 5

// Method value: bind sẵn vào instance cụ thể
p := &Point{3, 4}
scale := p.Scale
scale(2)
fmt.Println(p) // &{6 8}
Ý chính: Method là function gắn với một receiver type. Đây là cách Go cho phép type có “hành vi” mà không cần class như trong OOP truyền thống.
Quy tắc cần nhớ: Value receiver phù hợp khi method không sửa dữ liệu gốc và type đủ nhỏ để copy hợp lý. Pointer receiver phù hợp khi cần mutate hoặc muốn tránh copy lớn. Nếu biến là addressable value, Go có thể tự lấy địa chỉ để gọi pointer receiver method như p.Scale(2).
Lỗi hay gặp: Nếu một type có cả value receiver lẫn pointer receiver lẫn lộn không có chủ ý, method set và interface satisfaction dễ trở nên khó đoán. Nếu bất kỳ method nào thật sự cần pointer receiver, thường nên dùng pointer receiver nhất quán cho cả type.
Khi nào dùng: Dùng method khi hành vi gắn chặt với dữ liệu của type. Dùng method value khi muốn truyền “một hành vi đã bound sẵn vào object”, còn method expression khi muốn lấy method như một function tổng quát.
Generic functions & type inference
type parameters, inference, instantiation và khi nào nên dùng generics cho hàm
▼
genericstype paramsinferencetrung cấp
func Map[T, U any](items []T, fn func(T) U) []U {
    out := make([]U, len(items))
    for i, item := range items {
        out[i] = fn(item)
    }
    return out
}

labels := Map([]int{1, 2, 3}, func(n int) string {
    return fmt.Sprintf("n=%d", n)
})
fmt.Println(labels) // [n=1 n=2 n=3]

func Min[T cmp.Ordered](a, b T) T {
    if a < b {
        return a
    }
    return b
}

fmt.Println(Min(3, 5))      // type inference
fmt.Println(Min[int](3, 5)) // explicit instantiation
Ý chính: Generic function cho phép một hàm làm việc với nhiều type mà vẫn giữ type safety ở compile time. Đây là cách Go tái sử dụng thuật toán mà không phải rơi về any quá sớm.
Quy tắc cần nhớ: Go thường suy luận được type arguments từ input, nên nhiều lúc bạn không cần viết [T] tường minh. Khi compiler không suy luận nổi, bạn mới cần explicit instantiation như Min[int](3, 5).
Lỗi hay gặp: Đừng dùng generics chỉ để “trông hiện đại”. Nếu code chỉ phục vụ một type cụ thể hoặc abstraction làm API khó đọc hơn, hàm thường vẫn tốt hơn.
Đọc sau: Phần này là trực giác dùng generic functions trong thực tế. Constraint sâu hơn, union types và ~ nên xem kỹ thêm ở module generics và types.
