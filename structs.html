Khai báo struct, field & zero value
struct là value type, nhóm field liên quan, exported names và zero value của từng field
▼
structfieldszero valuenamingcơ bản
type User struct {
    Name   string
    Age    int
    Active bool
}

var u User
fmt.Println(u.Name, u.Age, u.Active) // "" 0 false

type Config struct {
    Host string
    Port int
}

cfg := Config{Host: "localhost", Port: 8080}
fmt.Println(cfg)
Ý chính: Struct là cách Go nhóm nhiều field có liên quan vào cùng một kiểu dữ liệu. Đây là nền tảng để mô hình hóa entity, config, request, response, và state trong hầu hết chương trình Go.
Quy tắc cần nhớ: Struct là value type. Mỗi field có zero value riêng của nó. Tên field bắt đầu bằng chữ hoa là exported để package khác hoặc các package như encoding/json có thể truy cập.
Lỗi hay gặp: Nhiều người mới quen OOP hay tìm constructor bắt buộc hoặc inheritance, nhưng Go không có class và cũng không có inheritance theo kiểu truyền thống.
Khi nào dùng: Dùng struct khi dữ liệu có nhiều thuộc tính đi cùng nhau và cần một tên kiểu rõ ràng thay vì truyền nhiều biến rời rạc.
Composite literals, copy & pointers
keyed literals, positional literals, struct copy, so sánh bằng và con trỏ tới struct
▼
literalcopypointercomparablecơ bản
type Point struct {
    X int
    Y int
}

type Profile struct {
    Name string
    Age  int
}

a := Point{1, 2}            // positional literal
b := Point{Y: 2, X: 1}      // keyed literal
fmt.Println(a == b)         // true nếu mọi field đều comparable

u1 := Profile{Name: "An", Age: 20}
u2 := u1                    // copy toàn bộ struct
u2.Age = 21
fmt.Println(u1.Age, u2.Age) // 20 21

p := &Profile{Name: "Binh"}
p.Age = 30                  // shorthand cho (*p).Age = 30
fmt.Println(p.Name, p.Age)
Ý chính: Gán một struct sang biến khác sẽ copy toàn bộ giá trị của struct đó. Con trỏ tới struct giúp nhiều nơi cùng thao tác trên cùng một instance hoặc tránh copy struct lớn.
Quy tắc cần nhớ: Ngoài phạm vi rất nhỏ, keyed literal như Profile{Name: "An"} thường dễ đọc và an toàn hơn positional literal. Struct chỉ so sánh được bằng == nếu tất cả field bên trong đều comparable.
Lỗi hay gặp: Người mới hay sửa bản copy rồi tưởng bản gốc thay đổi. Ngoài ra, positional literal dễ gãy khi thứ tự field đổi hoặc khi struct có nhiều field cùng kiểu.
Khi nào dùng: Dùng pointer khi cần mutate shared state hoặc struct lớn. Dùng value khi muốn bản sao độc lập, rõ ownership, hoặc struct nhỏ gọn.
Methods, constructor pattern & zero-value design
gắn hành vi vào struct, NewX pattern, pointer receiver và thiết kế zero value dùng được
▼
methodsconstructorreceivertrung cấp
type Counter struct {
    n int
}

func NewCounter(start int) *Counter {
    return &Counter{n: start}
}

func (c *Counter) Inc() {
    c.n++
}

func (c Counter) Value() int {
    return c.n
}

c := NewCounter(10)
c.Inc()
fmt.Println(c.Value()) // 11
Ý chính: Trong Go, “hành vi” của struct được gắn bằng method chứ không phải class. Nếu cần khởi tạo có logic hoặc muốn ẩn bớt chi tiết, idiom phổ biến là viết hàm kiểu NewX.
Quy tắc cần nhớ: Không phải struct nào cũng cần constructor. Rất nhiều type trong Go được thiết kế để zero value đã dùng được. Pointer receiver hợp khi cần mutate hoặc tránh copy lớn.
Lỗi hay gặp: Dùng lẫn lộn value receiver và pointer receiver mà không có chủ ý sẽ làm API khó đoán hơn, nhất là khi type cần implement interface.
Đọc sau: Phần method set, method value và method expression đã có một card sâu hơn trong module funcs. Ở đây mục tiêu là hiểu cách struct mang hành vi.
Struct embedding, composition & tags
anonymous fields, promoted fields, composition thay cho inheritance, interface embedding và struct tags
▼
embeddingcompositiontagstrung cấp
type Animal struct{ Name string }

func (a Animal) Speak() string {
    return a.Name + " speaks"
}

type Dog struct {
    Animal
    Breed string
}

d := Dog{
    Animal: Animal{Name: "Rex"},
    Breed:  "Lab",
}
fmt.Println(d.Name)    // promoted field
fmt.Println(d.Speak()) // promoted method

type ReadWriter interface {
    io.Reader
    io.Writer
}

type UserDTO struct {
    Name  string `json:"name"`
    Email string `json:"email,omitempty"`
    Age   int    `json:"-"`
}
Ý chính: Go ưu tiên composition hơn inheritance. Embedding cho phép một struct “mang theo” field và method của type khác theo cách đơn giản, rõ ràng hơn mô hình kế thừa nhiều tầng.
Quy tắc cần nhớ: Promoted field/method chỉ là cú pháp thuận tiện; bản chất vẫn là truy cập qua field được embed. Struct tag chỉ là metadata dạng chuỗi, có ý nghĩa khi package khác như encoding/json hoặc ORM đọc chúng bằng reflection.
Lỗi hay gặp: Embedding không phải inheritance. Nếu embed nhiều type có field hay method cùng tên, bạn có thể gặp ambiguous selector và phải gọi tường minh qua type bên trong.
Khi nào dùng: Dùng embedding khi muốn tái sử dụng hành vi nhỏ gọn hoặc ghép capability. Dùng struct tag khi cần mô tả cách serialize, validate, map DB, hoặc đọc metadata.
Interfaces & implicit implementation
small interfaces, duck typing, interface composition và nguyên tắc “accept interfaces, return concrete types”
▼
interfaceimplicitcompositiontrung cấp
type Reader interface {
    Read(p []byte) (int, error)
}

type Closer interface {
    Close() error
}

type ReadCloser interface {
    Reader
    Closer
}

type File struct{}

func (File) Read(p []byte) (int, error) { return 0, io.EOF }
func (File) Close() error               { return nil }

var rc ReadCloser = File{} // implement tự động, không cần từ khóa implements
Ý chính: Interface trong Go mô tả hành vi chứ không mô tả quan hệ kế thừa. Một type chỉ cần có đủ method là tự động implement interface đó.
Quy tắc cần nhớ: Interface nhỏ thường tốt hơn interface lớn. Một guideline phổ biến là “accept interfaces, return concrete types”: nhận dependency dưới dạng interface nhưng trả concrete type khi hợp lý để API vẫn giàu khả năng dùng.
Lỗi hay gặp: Người mới hay định nghĩa interface quá sớm hoặc quá to ở nơi consumer không cần. Trong Go, interface thường nên được đặt gần nơi sử dụng hơn là nơi implement.
Khi nào dùng: Dùng interface khi cần thay thế implementation, mock trong test, hoặc mô tả capability như đọc, ghi, log, cache, notify.
Nil interface, typed nil & comparison traps
nil interface vs interface chứa nil pointer, so sánh interface và các bẫy runtime phổ biến
▼
nil interfacetyped nilcomparisontrung cấp
type Stringer interface {
    String() string
}

type Person struct{ Name string }

func (p *Person) String() string {
    return p.Name
}

var p *Person = nil
var s Stringer = p

fmt.Println(p == nil) // true
fmt.Println(s == nil) // false

var x any = []int{1}
var y any = []int{1}
// fmt.Println(x == y) // panic: dynamic value []int không comparable
Ý chính: Một interface value gồm hai phần logic: dynamic type và dynamic value. Chỉ khi cả hai cùng nil thì interface mới thực sự bằng nil.
Quy tắc cần nhớ: var s Stringer = p với p là nil pointer vẫn tạo ra interface non-nil vì nó đã mang type *Person. Khi so sánh hai interface, nếu dynamic value bên trong không comparable như slice hoặc map, phép so sánh có thể panic ở runtime.
Lỗi hay gặp: Đây là một trong các bẫy nổi tiếng nhất của Go. Nó thường xuất hiện ở custom error type, logger, hoặc wrapper type trả về interface.
Khi nào dùng: Hiểu phần này đặc biệt quan trọng khi thiết kế API trả về error, fmt.Stringer, hoặc các interface custom khác.
Generic structs & container patterns
generic struct, comparable constraints và các container kiểu Stack / Set
▼
generic structconstraintscontainertrung cấp
type Stack[T any] struct {
    items []T
}

func (s *Stack[T]) Push(v T) {
    s.items = append(s.items, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.items) == 0 {
        var zero T
        return zero, false
    }
    n := len(s.items) - 1
    v := s.items[n]
    s.items = s.items[:n]
    return v, true
}

type Set[T comparable] map[T]struct{}

func (s Set[T]) Add(v T) {
    s[v] = struct{}{}
}
Ý chính: Generic struct giúp bạn viết một kiểu container hay helper dùng lại cho nhiều loại dữ liệu mà vẫn giữ type safety. Đây là nơi generics rất tự nhiên và có lợi thực sự.
Quy tắc cần nhớ: Nếu type parameter sẽ làm key của map hoặc cần so sánh bằng ==, constraint thường phải là comparable. struct{} thường được dùng làm value của set vì nó chiếm zero bytes về mặt ngữ nghĩa lưu trữ.
Lỗi hay gặp: Không phải mọi struct đều nên generic hóa. Với domain model cụ thể như User, Order, hay Invoice, generic thường chỉ làm API khó đọc hơn.
Đọc sau: Nếu cần đi sâu vào type parameters, inference, union constraints hay generic aliases, xem thêm module generics và một phần của types, funcs.
